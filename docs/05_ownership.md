## 所有権とは何か

Rustには、ガベージコレクション（GCによる自動メモリ管理）がない。その代わりに、**所有権**というルールをコンパイラがチェックすることで、メモリを安全に管理している。ルールは3つだけである。

1. それぞれの値は、所有者（owner）と呼ばれる変数を1つだけ持つ
2. 所有者がスコープを抜けると、値は破棄される
3. 値は、一度に1つの変数しか所有できない（代入すると、所有権は移動する）

## ムーブ：所有権の移動

`i32`のような単純な値と、`String`のような値とで、代入の挙動が違う。

```rust
fn main() {
    let x = 5;
    let y = x; // xの値がコピーされる
    println!("x = {}, y = {}", x, y); // 両方使える
}
```

```
x = 5, y = 5
```

一方、`String`では事情が異なる。

```rust
fn main() {
    let s1 = String::from("こんにちは");
    let s2 = s1; // 所有権がs1からs2へ移動する

    println!("{}", s2); // OK
    println!("{}", s1); // ← エラー！
}
```

```
error[E0382]: borrow of moved value: `s1`
```

`s2 = s1`の時点で、`s1`が持っていた所有権は`s2`に**移動（ムーブ）**する。ルール3「値は一度に1つの変数しか所有できない」により、元の`s1`はもう使えなくなる。

## なぜ挙動が違うのか

`i32`は固定サイズで、値そのものがスタックに積まれるため、コピーしても軽い。これらの型には`Copy`トレイトが付いており、代入のたびに自動でコピーされる。

`String`は、文字データの実体をヒープ（可変長のメモリ領域）に置き、変数自身はそこへのポインタを持つ構造である。もし代入のたびに中身までコピーしていたら、長い文字列ほど重くなってしまう。かといって、`s1`と`s2`の両方が同じヒープ領域を指したまま両方使えてしまうと、片方がスコープを抜けて解放したときに、もう片方が無効な領域を指すことになる（Cで実際に起こりうる不具合である）。

Rustは「両方使える」を諦める代わりに、「所有者は常に1つ」を保証することで、この種の不具合をコンパイル時に防いでいる。

## 関数に渡すときもムーブする

```rust
fn main() {
    let s = String::from("hello");
    takes_ownership(s);

    println!("{}", s); // ← エラー！ sはもう使えない
}

fn takes_ownership(text: String) {
    println!("{}", text);
}
```

```
error[E0382]: borrow of moved value: `s`
```

関数に`String`を渡すと、所有権は関数のパラメータに移動する。関数が終わるとパラメータはスコープを抜けて破棄されるため、呼び出し元の`s`はもう使えない。

## 練習問題

次のコードはエラーになる。なぜか説明したうえで、エラーを直してみよう（ヒント：`String`を2つ用意する）。

```rust
fn main() {
    let name = String::from("太郎");
    greet(name);
    greet(name); // ← ここでエラー
}

fn greet(name: String) {
    println!("こんにちは、{}さん", name);
}
```

**解答例を見る**

```rust
fn main() {
    let name1 = String::from("太郎");
    let name2 = String::from("太郎");
    greet(name1);
    greet(name2);
}

fn greet(name: String) {
    println!("こんにちは、{}さん", name);
}
```

1回目の`greet(name)`で所有権が関数に移動するため、2回目の`greet(name)`はもう存在しない値を使おうとしてエラーになる。今回は2つ用意したが、次回学ぶ「クローン」や「借用」を使えば、1つの`String`を何度も使い回すこともできる。
